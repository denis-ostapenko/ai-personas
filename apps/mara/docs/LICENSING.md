## Release rules

- Public descriptions, release notes and roadmap entries are provided in English and Brazilian Portuguese. Internal architecture, source identifiers, prompts and development notes are in English; source quotations retain their language.
- Document available functionality separately from future work. Keep repeated operational caveats out of the conversation screen; describe relevant constraints in setup, architecture and data documentation.
- Package source, guides and reproducible checks. Exclude API keys, environment files, databases, backups, private conversations and the surrounding research library.
- Changes to learning gates need explicit criteria and new evaluation material. Preserve unsuccessful results and distinguish controller checks from observed model behavior.
- Publication is a separate owner-authorized action. Local preparation does not create a GitHub repository, remote, push, release or deployment.
